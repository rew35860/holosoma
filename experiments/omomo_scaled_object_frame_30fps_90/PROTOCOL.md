# OMOMO 90 clips: scaled objects with OmniRetarget object-frame height

This uses the frozen 90-clip OMOMO cohort (15 each: largebox, plasticbox, smallbox, suitcase, whitechair, woodchair) and the same 30 FPS SMPL-X HOI inputs and metrics as `retarget_eval/omomo_scaled_world_30fps_90`. The only changed Omni target rule is object height. All Omni solves are fresh. The 90 UMR scaled-object solves from the previous comparison are reused byte-for-byte, verified by hash and shape. Thus UMR is the unchanged reference arm, not rerun.

For each clip Omni uses its native human scale `s = 1.32 / source_height`. Human joints are translated by its original toe/mat offset and then scaled. The object's local mesh, collision geometry, and contact points are uniformly scaled by `s`; orientation is unchanged. Its object translation follows `x'=s*x`, `y'=s*y`, and `z'=z0+s*(z-z0)`, where `z0` is the first source object Z. This keeps the first object height fixed and scales later vertical displacements around it. The prior world-scaled experiment instead used `z'=s*(z-z_min)` after the same XY/local mesh scaling. This object-frame rule is the original upstream Omni floor-rest height branch. The local modified original mode also has a HUMOTO-specific hand proximity heuristic that can choose another branch; this experiment explicitly applies the floor-rest rule to every OMOMO clip to test the requested object-frame policy. No solver constraints, weights, 30 FPS foot detection rule, or UMR outputs were changed.

The original 90-clip `sequence_manifest.json` and SMPL-X input hashes are checked in `prepare.py`; all six native Omni scene assets are copied with hashes from the previous isolated worktree. `preflight.json`, `input_audit.json`, and `local_assets.json` record provenance. Object-frame output is saved only under `retarget_eval/omomo_scaled_object_frame_30fps_90`; the world-scaled outputs are untouched.

Metric definitions are identical to the world-scaled evaluation. `evaluate.py` imports the same frozen `retarget_eval/reproduction_fullsize_30fps_90/snapshots/eval_main.py` and uses the same MuJoCo 3.10.0 G1/CoACD scene policy, scaled to each method's target. Success requires a complete finite 30 FPS solve at full clip length; actual infeasible solves count as failures in the 90-clip denominator. Object and ground penetration are the mean across clips of each clip's 95th-percentile deepest robot penetration. Foot skating is horizontal ankle speed at the original source stance frames. Contact recall/F1 use the frozen source labels, 20 mm hand-object threshold, and original no-source-contact convention. Joint error is mean pelvis-relative Euclidean error over the same 14 body landmarks. Quality means average each clip equally across clips successful for both methods. The definitions and thresholds were not changed for this run.

One CPU worker is launched in a user service with GPU visibility disabled, CPUQuota 75%, memory high 3 GiB/max 4 GiB/no swap, nice 19, and one BLAS/OpenMP thread. New clips wait for at least 8 GiB available memory; the worker terminates only its own child if memory drops below 4.5 GiB. The ongoing GPU training and HiPHI batch are not modified. `run_batch.py` is resumable and records a command, log, status, timing and SHA-256 per attempt, then updates the report after each clip. Infrastructure failures stop the batch for correction and are not counted as solver failures. `REPORT.md`, `summary.csv/json`, and `per_sequence.csv` are provisional until all 90 attempts finish.
